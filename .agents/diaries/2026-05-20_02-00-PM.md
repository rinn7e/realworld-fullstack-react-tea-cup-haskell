# Diary - May 20, 2026 (02:00 PM)

Today we completed a major backend refactoring task to clean up the API Data Transfer Objects (DTO) layer and fully integrate domain-specific type-safety across the application. 

Here is a summary of the achievements completed today:

## 1. Domain Type-Safety & Code Simplification
- **LogLevel Enum**: Replaced the custom serialization helpers (`logLevelToText` and `logLevelFromText`) and manual instances for `LogLevel` in `Domain/Type/Log.hs` with auto-derived `Generic` instances. It now derives `ToJSON`, `FromJSON`, `ToHttpApiData`, and `FromHttpApiData` automatically using GHC `anyclass` deriving, significantly reducing boilerplate.

## 2. Parameterized API Request Wrappers
To match the nested JSON payloads required by the RealWorld API specification (e.g. `{"article": ...}`, `{"comment": ...}`, `{"user": ...}`), we introduced generic, reusable request wrappers:
- `ArticleWrapper a` in `Infrastructure/Api/DTO/Article.hs`
- `CommentWrapper a` in `Infrastructure/Api/DTO/Comment.hs`
- `UserWrapper a` in `Infrastructure/Api/DTO/User.hs`

These wrappers allow us to automatically derive `FromJSON` and `ToSchema` instances for request payloads like `NewArticleRequest`, `UpdateArticleRequest`, `NewCommentRequest`, `LoginUserRequest`, `NewUserRequest`, and `UpdateUserRequest`, eliminating manual parsing and custom schema definitions.

## 3. Servant Route & Controller Adjustments
- Updated all Web and Admin route type definitions (`Web/Type.hs`) to expect the wrapped versions of the request bodies.
- Refactored corresponding controller handlers to pattern match against the generic wrappers (e.g. `ArticleWrapper`, `CommentWrapper`, `UserWrapper`) to extract payloads cleanly.
